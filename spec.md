# Спецификация busbot

Версия: MVP 0.2 · Дата: 2026-10-05 · Статус: личный тест, до 5 пользователей.

## 1. Назначение
Пассажир не хочет стоять на остановке и ждать. Бот в Telegram заранее (за N минут) предупреждает, что нужный маршрут подъезжает к выбранной остановке. Город — Красноярск, но кода, привязанного к городу, нет (кроме `YANDEX_TZ` и примеров).

### 1.1 Цели MVP
- Пользователь выбирает остановку за 1–2 действия: геометка, ссылка или сохранённая остановка.
- Уведомление приходит, когда GPS-прогноз прибытия не превышает N минут.
- Работает на домашнем сервере без платных API.

### 1.2 Вне рамок
- Коммерческая эксплуатация. Источник неофициальный, для продукта нужен договор с МКУ «Красноярскгортранс».
- Построение маршрутов и пересадки, оплата проезда, веб-интерфейс.
- Обход капчи и антибот-защиты Яндекса.

## 2. Пользователи и доступ
| Роль | Как задаётся | Права |
|---|---|---|
| Тестировщик | `ALLOWED_USERS` (id через запятую; пусто — пускаются все) | все команды |
| Посторонний | не в списке | получает ответ «Доступ закрыт. Твой id: N», остальное игнорируется |
| Админ | `ADMIN_ID` | получает алерты о сбоях и восстановлении источников |

Все данные (оповещения, сохранённые остановки) привязаны к `chat_id`. Пользователь не видит и не может изменить чужие записи.

## 3. Функциональные требования

### 3.1 Выбор остановки
| ID | Требование |
|---|---|
| F-1 | Геометка (кнопка «📍 Моя геопозиция» или произвольная точка на карте) → до 6 ближайших остановок в радиусе 1.5 км, отсортированных по расстоянию. На кнопке: стрелка направления от метки, название, расстояние. |
| F-2 | Одноимённые остановки показываются отдельно (это разные стороны дороги). Кнопка «‹ Другие остановки» возвращает к списку. |
| F-3 | Ссылка из Яндекс.Карт: полная, короткая `yandex.ru/maps/-/…` (по редиректу) или голый `stop__N`. Принимается и вне диалога `/stop`. |
| F-4 | Карточка остановки: название (и пользовательское имя, если остановка сохранена), по кнопке на каждый маршрут с ближайшим прибытием. Если GPS-прогнозов нет — предупреждение. |
| F-5 | Ошибки источника превращаются в понятный текст: таймаут, неверная ссылка, ссылка ведёт не на остановку, блокировка. |

### 3.2 Сохранённые остановки (`/stops`)
| ID | Требование |
|---|---|
| F-6 | «⭐ Сохранить остановку» на карточке, затем ввод своего названия (до 40 символов) или «Оставить» исходное. Пара (chat, stop) уникальна; повторное сохранение переименовывает. |
| F-7 | В `/stop` сохранённые остановки идут первыми кнопками. |
| F-8 | `/stops` показывает список. По нажатию — табло: до 3 ближайших GPS-прибытий по каждому маршруту; если их нет — до 2 по расписанию с пометкой «(расп.)»; если и их нет — интервал или «нет прогноза». Внизу время обновления. |
| F-9 | На табло кнопки: 🔔 оповещение, 🔄 обновить, ✏️ переименовать, 🗑 удалить (с подтверждением; оповещения по остановке при этом остаются), ‹ назад. |

### 3.3 Оповещения по остановке
| ID | Требование |
|---|---|
| F-10 | Порядок создания: маршрут → упреждение (3/5/7/10/15 мин) → режим («Один раз» / «Постоянно»). Ответ: «✅ Оповещение О{id}» с кнопкой «❌ Отключить». |
| F-11 | Срабатывание: ближайший будущий (ETA ≥ −1 мин) GPS-прогноз маршрута ≤ `lead_min`. Если GPS-прогноза нет и `STOP_USE_SCHEDULED=1`, учитывается расписание. |
| F-12 | Дедупликация: пара (триггер, vehicleId) срабатывает не чаще раза в 30 мин. Если vehicleId нет — не чаще раза в `lead_min + 3` мин. |
| F-13 | Режим «Один раз» отключается после первой отправки. «Постоянно» срабатывает на каждый следующий автобус. |
| F-14 | Текст: «🚌 **Автобус 135** будет на «X» через ~N мин (по GPS)». Если известен следующий автобус — «Следующий: через ~M мин». При ETA < 0.5 мин пишется «прямо сейчас». |
| F-15 | Прогноз, полученный больше `STOP_STALE` с назад, не используется. |

### 3.4 Управление
| ID | Команда | Поведение |
|---|---|---|
| F-16 | `/list` | Активные оповещения обоих режимов (О{id} — остановки, #{id} — геозоны) с кнопками отключения. |
| F-17 | `/now` | Ближайшие 3 прибытия по каждому оповещению и возраст данных; при проблеме источника — предупреждение. |
| F-18 | `/cancel`, `/help`, `/start` | Сброс диалога / справка с клавиатурой геометки. |
| F-19 | Меню команд | При запуске выставляется через `set_my_commands`. `/track` и `/where` попадают в меню только при `SOURCE=kgt`. |

### 3.5 Режим геозон (`/track`, требует `SOURCE=kgt`)
| ID | Требование |
|---|---|
| F-20 | Порядок создания: номер маршрута → точка → направление движения (8 румбов или «любое») → радиус (400/800/1500 м) → режим. |
| F-21 | Срабатывание: машина маршрута находится внутри радиуса. Если известен курс: при расстоянии > 50 м машина должна ехать к точке (допуск 80°), а при заданном направлении курс должен совпадать с ним (допуск 60°). Cooldown 15 мин на пару (триггер, борт). |
| F-22 | Уведомление содержит борт, расстояние, ETA (по скорости; если она меньше 5 км/ч или неизвестна — берётся 20 км/ч) и геометку машины. |
| F-23 | `/where <маршрут>` — до 8 свежих машин маршрута с координатами, курсом и возрастом данных. |

## 4. Источники данных

### 4.1 `STOP_SOURCE=yandex` (основной, HTTP)
- Прогноз: GET `https://yandex.ru/maps/{region}/{seoname}/stops/stop__N/` (до того как канонический URL станет известен — `/maps/?masstransit[stopId]=stop__N`). Из HTML берётся `<script class="state-view">`, путь `config.masstransitStop`. Это тот же JSON, что отдаёт `getStopInfo`. Время ответа около 1 с.
- Поиск рядом: GET `/maps/?ll={lon},{lat}&z=17&text=остановка`. Из state-view берутся объекты с `uri` вида `transit/stop?id=stop__N`, `title` и `coordinates`.
- Ограничения: не больше 2 одновременных запросов; одна попытка на остановку раз в `YANDEX_REFRESH`; ответы по запросам пользователя кешируются на 15–300 с в зависимости от сценария.
- Безопасность: не больше 6 редиректов, каждый проверяется на хосты `yandex.{ru,com,eu,kz,by,uz}`; итоговый путь должен начинаться с `/maps`.

### 4.2 `STOP_SOURCE=yandex_browser` (запасной)
Persistent-контекст Chromium (Playwright), по вкладке на остановку (не больше `YANDEX_MAX_STOPS`). Перехватываются ответы, URL которых содержит `YANDEX_STOP_PATTERN`. Работает медленно: страница сама запрашивает данные примерно через 30 с. Поиска по точке нет.

### 4.3 Формат прогноза (парсер `stopinfo.parse_stop_info`)
Ищется контейнер со списком `Transport`/`transports`. Каждый маршрут даёт `RouteForecast` с ключом `"<норм. номер>|<тип>"`. События берутся из `BriefSchedule.Events[]` (на уровне маршрута и `threads[]`): `Estimated` — GPS, `Scheduled` — расписание; дубли по (ts, vehicleId) отбрасываются. `currentTime` хранится как серверное время, `coordinates` — как `[lon, lat]`. Поддерживаемые форматы: 2019, 2019+ (`threads`), 2026 (проверен на живом Красноярске). Если формат не распознан, сырой JSON сохраняется в `YANDEX_DUMP_DIR`.

### 4.4 `SOURCE=kgt`
Произвольный JSON-эндпоинт с координатами машин. URL, метод, тело, заголовки, путь к списку, имена полей и масштаб координат задаются через `KGT_*`. Если курса нет, он вычисляется по смещению не меньше 10 м.

### 4.5 Mock
`STOP_SOURCE=mock` — маршруты 99, тролл. 7 и 135 с интервалом 10 мин; три фейковые остановки рядом с любой точкой. `SOURCE=mock` — фейковые координаты. Оба нужны только для разработки.

## 5. Обработка отказов
| Ситуация | Поведение |
|---|---|
| Капча / HTTP 403 / 429 | `SourceBlocked`: запросы на паузе `YANDEX_BLOCKED_PAUSE` (900 с), алерт админу, пользователю — «⛔ … Попробуй позже». Ничего не обходится. |
| Таймаут или сеть | Пользователю — «Яндекс не ответил вовремя». Движок пробует снова в следующем тике. |
| Ошибка одной остановки | В `problem()` попадает текст, отправляется алерт админу (один раз на каждый новый текст), после восстановления — «✅ … снова работает». |
| KGT недоступен | Экспоненциальный backoff до 300 с. После 5 ошибок подряд — алерт, после восстановления — сообщение об этом. |
| Telegram не принял сообщение | Ошибка логируется, движок продолжает работу. |

## 6. Данные (SQLite, `DB_PATH`)
| Таблица | Ключевые поля | Примечание |
|---|---|---|
| `stop_triggers` | chat_id, stop_id, stop_url, stop_name, route_key, route_title, lead_min, recurring, active | индекс (active, stop_id) |
| `saved_stops` | chat_id, stop_id, stop_url, title, yandex_name, lat, lon | UNIQUE(chat_id, stop_id), удаляется физически |
| `triggers` | chat_id, route, title, lat, lon, radius_m, bearing, recurring, active | режим геозон |

Отключённые оповещения остаются в таблице с `active=0`. Состояние диалогов (FSM), кеш снапшотов и cooldown-ы хранятся только в памяти.

## 7. Конфигурация
Полный список с комментариями — в `.env.example`. Обязателен только `BOT_TOKEN`. Основные параметры: `STOP_SOURCE`, `STOP_INTERVAL` (10 с), `STOP_STALE` (180 с), `STOP_USE_SCHEDULED` (0), `YANDEX_REFRESH` (30 с в примере), `YANDEX_BLOCKED_PAUSE` (900 с), `SOURCE`, `POLL_INTERVAL` (20 с), `STALE_AFTER` (120 с).

## 8. Нефункциональные требования
- Нагрузка на Яндекс: примерно 1 запрос в `YANDEX_REFRESH` на каждую остановку с активными оповещениями, плюс запросы пользователей. Не больше 2 одновременно.
- Задержка уведомления: не больше `YANDEX_REFRESH + STOP_INTERVAL` (около 40 с) после появления прогноза.
- Развёртывание: Docker (python:3.12-slim + Chromium, образ около 1 ГБ), `restart: unless-stopped`, `shm_size: 1gb`, том `./data:/data`.
- Ответ на действие пользователя: около 1–2 с (HTTP-источник).
- Диагностика: `python -m busbot.probe` проверяет источник без Telegram.

## 9. Тестирование
38 автотестов (`pytest -q`, все проходят):
- парсер на реальных ответах Яндекса (2019, 2026, поиск);
- `StopMatcher`/`Matcher`, движки на mock и SQLite с подменой времени;
- HTTP-источник против локальной имитации Яндекса: редиректы, капча, 403, сеть, чужой домен;
- диалоги через настоящий aiogram Dispatcher;
- Chromium против имитации (тесты пропускаются, если браузер не установлен).

Ручная приёмка: `probe` по реальной остановке днём показывает `GPS-прогнозов > 0`; затем создаётся оповещение «за 5 мин» и проверяется, что приходит ровно одно уведомление на автобус.

## 10. Известные ограничения и риски
| # | Риск / ограничение | Последствие | Что делать |
|---|---|---|---|
| R-1 | Неофициальный источник | Яндекс может сменить HTML или включить капчу, и бот перестанет работать | запасной `yandex_browser`, дампы для правки парсера; в перспективе — официальный API |
| R-2 | FSM и cooldown хранятся в памяти | после рестарта незаконченный диалог теряется; «постоянное» оповещение может повторно сработать на тот же автобус | для MVP допустимо; лечится `SQLiteStorage` и хранением `_fired` в БД |
| R-3 | Нет миграций схемы | изменение колонок ломает существующую БД | при изменении схемы добавить `ALTER` или версионирование |
| R-4 | Дефолты в `config.py` ≠ `.env.example` (`SOURCE`: mock/none, `YANDEX_REFRESH`: 60/30) | без `.env` поведение отличается от документации | выровнять дефолты |
| R-5 | `.env` с токеном лежит в корне, `.gitignore` нет | при `git init` токен утечёт в репозиторий | добавить `.gitignore` (`.env`, `data/`, кеши) |
| R-6 | Ночью или на некоторых остановках есть только расписание | GPS-оповещения не срабатывают | предупреждение на карточке; опция `STOP_USE_SCHEDULED` |
| R-7 | Docker-образ копирует `tests/` | лишние файлы в проде | некритично |

## 11. Дальнейшее развитие (не в MVP)
Официальный источник данных (КГТ), персистентный FSM, «тихие часы» и расписание оповещений по дням недели, автоочистка неактивных записей, метрики (число запросов к Яндексу, доля ответов без GPS).
