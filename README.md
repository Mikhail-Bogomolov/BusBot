# busbot — Telegram-оповещения о подходе автобуса (Красноярск, MVP)

Два режима:
- **Остановки (основной).** Прогноз прибытия из Яндекс.Карт: «Автобус 135 будет на «Остановке» через ~5 мин».
  Источник — обычная страница остановки Яндекс.Карт по HTTP: прогноз вшит в её HTML
  (`<script class="state-view">` → `config.masstransitStop`, тот же JSON, что у `getStopInfo`). ~1 с на остановку, без браузера.
  Запасной вариант `STOP_SOURCE=yandex_browser` — headless Chromium (медленно: страница сама запрашивает `getStopInfo` только через ~30 с).
- **/track — по точке на карте.** Геозона по координатам автобусов. Нужен источник координат (`SOURCE=kgt`, см. ниже); пока его нет — `SOURCE=none`.

## Запуск (Docker, домашний сервер)
```bash
cp .env.example .env            # вписать BOT_TOKEN, ALLOWED_USERS, ADMIN_ID
docker compose build            # ~1 ГБ образ: Python + Chromium
# 0) Telegram без VPN на сервере: ключ из Happ -> xray/config.json (см. раздел ниже)
docker compose run --rm --no-deps bot python -m busbot.tgproxy "<ключ vless://… или ссылка на подписку>"
# 1) проверить, что Яндекс отдаёт данные (без Telegram):
docker compose run --rm bot python -m busbot.probe "<ссылка на остановку>"
docker compose run --rm bot python -m busbot.probe 55.998,92.796      # ближайшие остановки к точке
docker compose run --rm bot python -m busbot.probe --line "<ссылка>" 3 30   # упреждение 30 мин для автобуса 3
# 2) запустить бота
docker compose up -d && docker compose logs -f
```
Ссылка на остановку: Яндекс.Карты → нажать на остановку (откроется табло прибытия) → Поделиться → Скопировать ссылку. Подходит и короткая `https://yandex.ru/maps/-/...`, и голый `stop__123456`.

Без Docker: `pip install -r requirements.txt && python -m busbot` (`.env` читается сам). Chromium (`python -m playwright install chromium`) нужен только для `STOP_SOURCE=yandex_browser` и браузерных тестов.

## Что показывает probe и что делать
| Результат | Значит | Действие |
|---|---|---|
| `OK`, маршруты с минутами | всё работает | запускать бота |
| `OK`, но `GPS-прогнозов: 0` | у Яндекса по этой остановке только расписание (или ночь) | проверить днём; либо `STOP_USE_SCHEDULED=1` |
| `TimeoutError` + список API-запросов | Яндекс переименовал метод | найти в списке запрос с прогнозом и вписать часть его пути в `YANDEX_STOP_PATTERN` |
| `формат ответа не распознан` | изменился JSON | прислать файл из `data/yandex_dump/` — парсер поправляется в `busbot/stopinfo.py` |
| `HTTP 403/429` или `капчу` | Яндекс считает нас ботом | не обходить: подождать, увеличить `YANDEX_REFRESH`, уменьшить число остановок |
| `--line`: `нет схемы (masstransitLine)` | Яндекс изменил страницу маршрута | оповещения работают в пределах ~15 мин; парсер схемы — `parse_line` в `busbot/stopinfo.py` |
| `--line`: `Контрольных остановок нет` | остановка в начале маршрута (рядом конечная) | раньше ~15 мин здесь не предупредить; это не ошибка |

## Команды бота
Меню команд (кнопка «Меню» у поля ввода) бот выставляет сам при запуске (`set_my_commands`).
`/stop` — новое оповещение · `/stops` — мои остановки и табло · `/list` — оповещения с кнопками отключения · `/now` — прогноз по оповещениям · `/cancel` · `/help`. `/track`, `/where` — режим геозон, в меню только при `SOURCE=kgt`.
Не в `ALLOWED_USERS` → бот отвечает «Доступ закрыт» и пишет id: так удобно собрать id тестеров.

Как выбрать остановку (в `/stop` или просто так, без команды):
- **Геометка** — кнопка «📍 Моя геопозиция» или 📎 → Геопозиция → метка в любом месте карты. Бот ищет «остановка» на Яндекс.Картах вокруг точки и показывает до 6 ближайших (до 1.5 км) со стрелкой направления и расстоянием. Одноимённые остановки — обычно разные стороны дороги; кнопка «‹ Другие остановки» возвращает к списку.
- **Ссылка** из Яндекс.Карт (нажать на остановку → Поделиться), подходит и короткая `https://yandex.ru/maps/-/...`, и голый `stop__123456`.
- **Сохранённая** — «⭐ Сохранить остановку» на карточке остановки, затем своё название («Дом», «Универ»). Они идут первыми кнопками в `/stop`; в `/stops` — табло прибытия, оповещение, переименование, удаление.

## Как работает режим остановок
- Остановки с активными оповещениями обновляются раз в `YANDEX_REFRESH` с (по умолчанию 30), не больше 2 запросов к Яндексу одновременно. Выбор остановки/табло — запрос «по требованию», ответ кешируется на 15–60 с.
- Оповещение срабатывает, когда ближайший **GPS-прогноз** (не расписание) ≤ N мин. Один и тот же автобус (vehicleId) — одно уведомление; следующий автобус — новое. «Один раз» отключается после первого.
- Время прибытия считается по часам Яндекса из ответа, расхождение часов сервера не влияет.
- **Упреждение 20–40 мин.** Яндекс показывает автобус на остановке примерно за 15 мин (`YANDEX_HORIZON`). Для более раннего оповещения бот берёт со страницы маршрута порядок остановок и следит ещё за 1–4 остановками выше по ходу: автобус, который Яндекс видит там, переносится на вашу остановку с добавлением времени в пути. Время в пути бот учит сам по реальным проездам тех же автобусов (таблица `segment_times`), поэтому после первого-второго автобуса оценка учитывает пробки. До этого он считает по средней скорости 18 км/ч, и первые оценки бывают оптимистичны на несколько минут. При `SOURCE=kgt` дополнительно используются координаты автобусов КГТ. В уведомлении и в `/now` это помечено как оценка (`≈`). Если остановка рядом с началом маршрута, бот при создании честно скажет, за сколько минут реально сможет предупредить. Выключается `UPSTREAM=0`. Каждая такая остановка — ещё один регулярный запрос к Яндексу.
- Капча или HTTP 403/429 → запросы на паузе `YANDEX_BLOCKED_PAUSE` (15 мин) + алерт админу. Капча не решается и не обходится. Редиректы проверяются на каждом шаге — ссылка не может увести бота с доменов Яндекса.

## Ограничения и риски — читать до демо
- Это неофициальный способ: Яндекс может в любой момент поменять страницу/API или начать показывать капчу. Для личного теста на 5 человек — ок; **продукт на продажу на этом строить нельзя**, нужен официальный источник (запрос в МКУ «Красноярскгортранс»).
- Формат проверен на живом Яндексе (октябрь 2026, Красноярск). Если Яндекс уберёт данные из HTML — `STOP_SOURCE=yandex_browser` как запасной вариант, парсер общий.
- Привязка к остановке; геометка лишь помогает её найти. Геозоны — режим `/track` при наличии координат.

## Подключение KGT для /track (SOURCE=kgt)
DevTools → Network → Fetch/XHR на карте mu-kgt.ru → найти запрос с массивом машин → URL и имена полей в `.env` (`KGT_*`). Проверка: `/where <маршрут>`.

## Telegram без VPN на сервере
С сервера Telegram недоступен, а VPN на всём сервере мешает: Яндекс видит заграничный IP. Поэтому в `docker-compose.yml` рядом с ботом работает контейнер `tg-proxy` (Xray, тот же движок, что в Happ). Через него идёт только трафик бота к Telegram (`TELEGRAM_PROXY=socks5://tg-proxy:1080`), Яндекс и всё остальное на сервере — напрямую. VPN на сервере включать не нужно.

1. Взять ключ: в Happ скопировать сервер (ссылка `vless://…`) или ссылку на подписку из кабинета/бота VPN-сервиса (`https://…`). Подходят `vless://` (Reality, TLS, ws, grpc, xhttp, httpupgrade), `vmess://`, `trojan://`, `ss://`. Зашифрованные `happ://crypt…` и `hysteria2://` не подходят: нужен обычный ключ или подписка.
2. Сделать конфиг. На сервере:
   ```bash
   docker compose run --rm --no-deps bot python -m busbot.tgproxy "<ключ или ссылка на подписку>"
   ```
   Либо на своём компьютере: `python -m busbot.tgproxy "<ключ>"`, затем скопировать папку `xray/` на сервер рядом с `docker-compose.yml`. Скрипт выводит список серверов без секретов и записывает в `xray/config.json` первый подходящий. Чтобы выбрать другой, добавь его номер после ключа: `... "<подписка>" 3`.
3. `docker compose up -d`. В `docker compose logs` должно быть `Xray 26.9.30 started` у `tg-proxy` и `telegram via proxy socks5://tg-proxy:1080` у бота.

Сменить сервер: заново шаг 2, затем `docker compose restart tg-proxy`. В `xray/config.json` лежит ключ VPN, поэтому папка в `.gitignore`. Порт 1080 наружу не публикуется: прокси без пароля и доступен только боту внутри сети compose. Если VPN-сервис ограничивает число устройств, сервер займёт одно место. Не задавай `HTTP_PROXY`/`HTTPS_PROXY` в окружении: их подхватит клиент Яндекса.

Образы (`python:3.12-slim`, `ghcr.io/xtls/xray-core`) и Chromium скачиваются один раз при сборке. Если без VPN сервер их не скачивает, собери один раз с VPN, дальше он не нужен.

Без Docker (локально): `TELEGRAM_PROXY=socks5://127.0.0.1:<порт>` в `.env`, где порт — SOCKS-порт Happ/v2rayN в режиме прокси. Поддерживаются `http`, `socks4`, `socks5`.

## Тесты
`pytest -q` — 65 тестов: Telegram через прокси (HTTP CONNECT и цепочка бот → SOCKS5 → настоящий Xray → VLESS → имитация Telegram), разбор ключей vless/vmess/trojan/ss и подписки, проверка каждого конфига самим Xray (`xray run -test`); упреждение сверх 15 мин (реальная схема маршрута 3, симуляция автобусов с обучением времени в пути, координаты КГТ); HTTP-источник против локальной имитации Яндекса (реальные ответы Красноярска: страница остановки, поиск, редиректы, капча, 403, сеть); диалоги геометка → ближайшие → сохранение → `/stops`; парсер на реальном примере ответа Яндекса (2019) и формате с `threads`; матчер; движки на mock + SQLite с симуляцией времени; диалоги бота через настоящий aiogram Dispatcher; **настоящий Chromium против локальной имитации Яндекса** (короткая ссылка с редиректом, наблюдение + перезагрузка вкладки, капча, 403, 404, таймаут, чужой домен, протухший lock профиля). Браузерные тесты пропускаются, если Chromium не установлен (`python -m playwright install chromium` или `CHROME_PATH`); тесты с Xray — если нет `xray` в PATH или `XRAY_PATH`.
